- 这个问题我从上周五做到这周二，中间又出现了大量的懈怠时间
- 作为定长滑动模板，这个题是很容易套模板的，最终的时间复杂度是 O(52(m+n))
- 但是作为1个困难题，题解中也有是否能优化到 O(m+n) 的提示，所以一直在纠结
- 灵神给出了两种解法，一种是套模板，和我的一样，除了以下区别
  - 同样的把更新答案判断放到了左端移出循环里，并在左端移出操作前
  - 对于String截取操作优化，只记录符合答案的左右下标
- 另一种 O(m+n) 的解法，其实我也摸到了思路，但是最终没有写出来
- 灵神的最优解法，是维护 s 中有多少种字符，数量超过了 t 中的字符数量
  - 这里我没想到的一点是，通过判断 **更新后**的字符数量==0，来判断是否又新有了一种字符满足条件
  - 原因是更新了更新后的值为0, 说明之前为负数，那么就是之前不满足，更新后满足
  - *我一直想着通过正数、负数或大小来判断，结果逻辑越来越绕*
  - 通过 临界值 == 0，说明之前在临界值之下，那么 判断 更新后临界值==0,是一个很实用的思考方式
